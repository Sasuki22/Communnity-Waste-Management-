# Admin Contact Inbox Design

The existing public contact form stores messages in `contact_messages` but does not expose them to administrators. Add a Contact sidebar tab immediately below Announcements in `admin_modern.php`; render the newest messages as responsive cards with name, Gmail address, message and submission time, using escaped output. Read them through a GET-only, session-admin-protected `admin_api.php?action=contact_messages` endpoint. Show loading, empty and error states and refresh on tab selection.

The public `contact.php` accepts only syntactically valid `@gmail.com` addresses, normalized to lowercase. Allow one successful message per address per server UTC calendar day; the next UTC day permits another. Use a separate `contact_daily_limits` table with primary key `(email, submitted_on)` to atomically reserve each day's slot in a transaction alongside insertion into the existing `contact_messages`. Roll back on storage failure; return HTTP 429 for an already-used slot. The public table remains intact, including older messages. Concurrent attempts must not create duplicates. The existing client disables the submit button in flight, but server enforcement is authoritative.

Do not introduce external dependencies, email sending, message deletion, user-account requirements, or wholesale database imports. Before deploying, back up live files/database; the production DB user needs CREATE TABLE permission or the daily-limit table must be created by an administrator using the matching schema. Never upload tests or private SQL files to `public_html`.
